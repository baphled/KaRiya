## What I do

Automatically rebase PRs onto their target branch and resolve any merge conflicts that arise. This keeps PRs up-to-date and mergeable without manual intervention.

## When to use me

Use this skill when:
- PR monitoring detects branch is behind target
- PR shows "needs rebase" or merge conflicts
- CI fails due to outdated base branch
- Before merging to ensure clean history

## Automatic Rebase Process

### 1. Check If Rebase Needed

```bash
# Fetch latest from remote
git fetch origin

# Check if behind target branch
BASE_BRANCH=$(gh pr view --json baseRefName -q '.baseRefName')
COMMITS_BEHIND=$(git rev-list --count HEAD..origin/$BASE_BRANCH)

if [ "$COMMITS_BEHIND" -gt 0 ]; then
    echo "Branch is $COMMITS_BEHIND commits behind $BASE_BRANCH"
    # Rebase needed
fi
```

### 2. Perform Rebase

```bash
# Ensure clean working directory
git stash --include-untracked

# Rebase onto target
git rebase origin/$BASE_BRANCH
```

### 3. Handle Conflicts Automatically

When conflicts occur, resolve them intelligently:

#### Strategy 1: Theirs for Generated Files

For generated files, lock files, or files we didn't modify:

```bash
# Accept theirs for files we didn't change
git checkout --theirs <file>
git add <file>
```

#### Strategy 2: Ours for Our Changes

For files we intentionally modified:

```bash
# Keep our version
git checkout --ours <file>
git add <file>
```

#### Strategy 3: Smart Merge for Code Files

For code conflicts, analyse and merge intelligently:

```bash
# Get conflict markers
grep -n "<<<<<<< HEAD" <file>

# Analyse both versions
# Apply appropriate resolution based on:
# - Which changes are newer
# - Which changes are from our PR
# - Whether changes are complementary or contradictory
```

### 4. Continue Rebase

```bash
# After resolving conflicts
git rebase --continue

# If more conflicts, repeat resolution
# Until rebase completes
```

### 5. Force Push (Safe)

```bash
# Push rebased branch
git push --force-with-lease origin HEAD

# --force-with-lease prevents overwriting others' work
```

## Conflict Resolution Rules

### Accept Theirs (Target Branch)

| File Type | Reason |
|-----------|--------|
| `go.sum` | Regenerated by go mod |
| `go.mod` (dependencies only) | Will be resolved by go mod tidy |
| Generated files (`*_gen.go`) | Will be regenerated |
| Lock files | Should match target branch |

### Keep Ours (Feature Branch)

| File Type | Reason |
|-----------|--------|
| Files we intentionally modified | Our changes are the goal |
| New files we added | Not in target branch |
| Test files for our feature | Specific to our changes |

### Manual Merge Required

| Situation | Action |
|-----------|--------|
| Both sides modified same function | Combine changes logically |
| Conflicting business logic | Understand intent, merge carefully |
| Schema/migration conflicts | May need new migration |

## Implementation

```go
// Pseudo-code for conflict resolution logic
func resolveConflict(file string, oursContent, theirsContent []byte) ([]byte, error) {
    // Check if file is in "accept theirs" list
    if isGeneratedFile(file) || isLockFile(file) {
        return theirsContent, nil
    }
    
    // Check if we created this file
    if !existsInBase(file) {
        return oursContent, nil
    }
    
    // Check if only we modified it
    if !modifiedInTarget(file) {
        return oursContent, nil
    }
    
    // Check if only they modified it
    if !modifiedInOurs(file) {
        return theirsContent, nil
    }
    
    // Both modified - attempt smart merge
    return smartMerge(file, oursContent, theirsContent)
}
```

## Rebase Workflow Integration

### During PR Monitoring

```
PR Monitor detects:
    │
    ├─ Branch behind target?
    │   └─ Yes → Trigger auto-rebase
    │
    ├─ Conflicts detected?
    │   ├─ Auto-resolvable → Resolve and continue
    │   └─ Manual needed → Pause and report
    │
    └─ Rebase complete?
        ├─ Success → Push and continue monitoring
        └─ Failed → Report and ask for help
```

### Commands

```bash
# Check rebase status
git status

# View conflicts
git diff --name-only --diff-filter=U

# Abort if needed
git rebase --abort

# Skip problematic commit (rare)
git rebase --skip
```

## Safety Measures

### Before Rebase

- [ ] Stash any uncommitted changes
- [ ] Verify we're on correct branch
- [ ] Fetch latest from remote
- [ ] Create backup branch (optional)

### During Rebase

- [ ] Never force-push to shared branches
- [ ] Use `--force-with-lease` not `--force`
- [ ] Abort if unsure about conflict resolution

### After Rebase

- [ ] Verify all tests still pass
- [ ] Check no unintended changes
- [ ] Confirm CI runs on new commits

## Error Recovery

### Rebase Gone Wrong

```bash
# Abort current rebase
git rebase --abort

# Reset to remote state
git fetch origin
git reset --hard origin/feature/my-feature
```

### Wrong Conflict Resolution

```bash
# If already pushed, create fixup commit
git revert <bad-commit>

# Or if not pushed, reset and retry
git reset --hard HEAD~1
git rebase origin/next
```

## Anti-Patterns

**DON'T:**
- Force push to `main` or `next` branches
- Rebase commits that others have based work on
- Accept conflicts blindly without understanding
- Skip commits without understanding why

**DO:**
- Always use `--force-with-lease`
- Understand each conflict before resolving
- Test after rebase completes
- Communicate if rebase affects others
