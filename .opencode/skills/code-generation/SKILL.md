## What I do

Guide effective use of code generation in Go - mocks, stringers, templates, and custom generators to reduce boilerplate while keeping code maintainable.

## When to use me

- Setting up mock generation
- Creating enum stringers
- Writing custom generators
- Reducing repetitive code
- Reviewing generated code practices

## Core Principles

1. **Generate what's tedious** - Don't generate what's easy to write
2. **Track generated files** - Know what's generated vs hand-written
3. **Regenerate in CI** - Ensure generated code stays current
4. **Document the generator** - Make it clear how to regenerate

## go:generate Basics

### Directive Format

```go
//go:generate command arguments...

// Examples
//go:generate mockgen -source=repository.go -destination=mock_repository.go
//go:generate stringer -type=Status
//go:generate go run generate_handlers.go
```

### Running Generators

```bash
# Generate in current package
go generate

# Generate recursively
go generate ./...

# Verbose output
go generate -v ./...

# Generate specific file
go generate repository.go
```

## Mock Generation (mockgen)

### Source Mode (Recommended)

```go
// internal/service/event_service.go

//go:generate mockgen -source=event_service.go -destination=mock_event_service.go -package=service

type EventRepository interface {
    FindByID(id string) (*Event, error)
    Save(event *Event) error
    Delete(id string) error
}

type EventService struct {
    repo EventRepository
}
```

### Reflect Mode (For External Interfaces)

```go
// internal/service/generate.go

//go:generate mockgen -destination=mock_io.go -package=service io Reader,Writer
```

### Usage in Tests

```go
func TestEventService_Get(t *testing.T) {
    ctrl := gomock.NewController(t)
    defer ctrl.Finish()
    
    mockRepo := NewMockEventRepository(ctrl)
    mockRepo.EXPECT().
        FindByID("123").
        Return(&Event{ID: "123", Name: "Test"}, nil)
    
    svc := NewEventService(mockRepo)
    event, err := svc.Get("123")
    
    require.NoError(t, err)
    assert.Equal(t, "Test", event.Name)
}
```

### Centralised Mock Generation

```go
// internal/mocks/generate.go

package mocks

// Repository interfaces
//go:generate mockgen -destination=mock_event_repository.go -package=mocks github.com/baphled/kariya/internal/repository EventRepository
//go:generate mockgen -destination=mock_skill_repository.go -package=mocks github.com/baphled/kariya/internal/repository SkillRepository

// Service interfaces
//go:generate mockgen -destination=mock_event_service.go -package=mocks github.com/baphled/kariya/internal/service EventService
```

## Stringer (Enum Strings)

### Basic Usage

```go
// internal/domain/status.go

//go:generate stringer -type=Status

type Status int

const (
    StatusPending Status = iota
    StatusActive
    StatusCompleted
    StatusCancelled
)

// Generated: status_string.go
// func (s Status) String() string { ... }

// Usage
fmt.Println(StatusActive)  // "StatusActive"
```

### With Trimprefix

```go
//go:generate stringer -type=EventType -trimprefix=EventType

type EventType int

const (
    EventTypeMeeting EventType = iota
    EventTypeTask
    EventTypeNote
)

// Generated strings: "Meeting", "Task", "Note"
```

## Custom Generators

### Simple Template Generator

```go
// tools/generate_handlers.go
//go:build ignore

package main

import (
    "os"
    "text/template"
)

var handlerTemplate = `// Code generated by generate_handlers.go; DO NOT EDIT.

package handlers

{{range .Entities}}
func Handle{{.Name}}(w http.ResponseWriter, r *http.Request) {
    // Generated handler for {{.Name}}
}
{{end}}
`

func main() {
    entities := []struct{ Name string }{
        {"Event"},
        {"Skill"},
        {"Project"},
    }
    
    f, _ := os.Create("generated_handlers.go")
    defer f.Close()
    
    tmpl := template.Must(template.New("handlers").Parse(handlerTemplate))
    tmpl.Execute(f, map[string]interface{}{"Entities": entities})
}
```

### Using in Package

```go
// handlers/handlers.go

//go:generate go run ../tools/generate_handlers.go
```

## Generated File Conventions

### Naming

```
{original}_gen.go        # Generated from original
{original}_string.go     # Stringer output
mock_{original}.go       # Mock output
{original}_easyjson.go   # JSON generator output
```

### Header Comment

```go
// Code generated by {tool}; DO NOT EDIT.

package mypackage
```

### Git Handling

```bash
# Option 1: Commit generated files (recommended for most cases)
# - Ensures builds work without generators
# - Makes PRs reviewable
# - CI can verify freshness

# Option 2: Gitignore and generate in CI
# .gitignore
*_gen.go
mock_*.go
*_string.go
```

## CI Integration

### Verify Generated Code is Fresh

```yaml
# .github/workflows/ci.yml
- name: Generate code
  run: go generate ./...

- name: Check for changes
  run: |
    if [ -n "$(git status --porcelain)" ]; then
      echo "Generated code is out of date. Run 'go generate ./...'"
      git diff
      exit 1
    fi
```

### Makefile Target

```makefile
.PHONY: generate
generate:
	go generate ./...

.PHONY: generate-check
generate-check: generate
	@if [ -n "$$(git status --porcelain)" ]; then \
		echo "Generated code is out of date"; \
		git diff; \
		exit 1; \
	fi
```

## Best Practices

### DO

- Add `// Code generated ... DO NOT EDIT.` header
- Commit generated files (usually)
- Verify freshness in CI
- Document how to regenerate
- Use `-destination` flag for predictable output

### DON'T

- Edit generated files manually
- Generate code that's easy to write
- Forget to regenerate after interface changes
- Use generators without understanding output

## Troubleshooting

### "command not found"

```bash
# Install the tool
go install golang.org/x/tools/cmd/stringer@latest

# Ensure GOBIN is in PATH
export PATH=$PATH:$(go env GOBIN)
```

### Generated code is stale

```bash
# Regenerate all
go generate ./...

# Check what changed
git diff
```

### Mock doesn't match interface

```bash
# Regenerate mocks
go generate ./internal/mocks/...

# Verify interface matches
go build ./...
```
