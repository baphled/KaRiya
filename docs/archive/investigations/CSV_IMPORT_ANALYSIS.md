## Import Process Details

### Source Data Format

**File Structure**:
```
Text | Date | Categories | Tags | Project | Company
```

**Example Rows**:
```
Architected and maintained custom Linux infrastructure... | 2000-01 | SysAdmin;Infrastructure | linux;golden-discs | | RWDMag
Implemented event classification service... | 2025-02 | Backend;Features | classification;ml;competencies | KaRiya |
```

**Data Characteristics**:
- **Format**: Pipe-delimited (`|`)
- **Date Format**: YYYY-MM (automatic conversion to YYYY-MM-01)
- **Categories**: Semicolon-separated list
- **Tags**: Semicolon-separated list
- **Optional Fields**: Project, Company (may be empty)
- **Text Field**: Rich descriptions (50-400 characters typical)

### Mapping Strategy

**Categories Mapping**:
The CSV categories (SysAdmin, Content, etc.) are mapped to KaRiya's 6 competency categories:
1. **Technical**: Backend, Frontend, Infrastructure, DevOps, Hardware
2. **Leadership**: Management, Strategy, Vision, Coordination
3. **Product**: Product, Feature Design, Customer Focus
4. **Consulting**: Advisory, Transformation, Optimization
5. **Research**: Investigation, Data Analysis, Methodology
6. **Mentoring**: Coaching, Training, Skill Development

**Tags Mapping**:
KaRiya supports up to 8 tags per event from the defined AllowedTags set. The import system:
- Preserves original domain-specific tags (ruby, php, api, etc.)
- Maps domain-specific tags to KaRiya's standardized set
- Removes duplicates automatically
- Enforces 8-tag maximum per event
